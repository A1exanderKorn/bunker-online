# Выкладка на VPS

## Требования

Поддерживаемый Debian 12/13, Git, Docker Engine с плагином Compose v2,
пользователь с sudo. Установка Docker: https://docs.docker.com/engine/install/debian/.
Открыть входящие TCP 80/443 и UDP 443 (опционально для HTTP/3); SSH 22 оставить доступным.
Порт приложения 3000 наружу не публикуется. Служба Docker должна быть включена
через `sudo systemctl enable --now docker`.

На проверенном 23.09.2026 VPS с IP 89.169.189.113 установлен Debian 11.
Его LTS завершилась, репозиторий security возвращает 404 для Git.
До публичного запуска нужно обновить ОС или пересоздать VPS на поддерживаемой версии.
Выкладка на этом сервере пока НЕ выполнена.

## Первый запуск

Из PowerShell (ключ хранить только на своём компьютере, не в репозитории):

```powershell
ssh -i "$env:USERPROFILE\.ssh\bunker-vps-deploy" user@89.169.189.113
```

На VPS:

```bash
git clone --branch master --single-branch https://github.com/A1exanderKorn/bunker-online.git
cd bunker-online
bash deploy/deploy.sh
curl --fail http://127.0.0.1/health
```

Без настройки домена игра работает по HTTP на IP сервера. Caddy проксирует
и обычные запросы, и WebSocket. Контейнеры запускаются после перезагрузки.
Нужно отдельно проверить с другого компьютера главную страницу, `/health`
и создание/подключение к лобби: локальный healthcheck не проверяет облачный firewall.

## Обновление после push в master

```bash
cd ~/bunker-online
bash deploy/deploy.sh
```

Push сам по себе НЕ обновляет VPS. Скрипт получает `origin/master`, требует
чистую рабочую копию, собирает образ с тегом коммита, проверяет запуск и при
ошибке пытается вернуть предыдущий образ приложения. Неудачная сборка не
останавливает текущую игру. Замена запущенного контейнера прерывает партии:
лобби пока находятся в оперативной памяти. Обновляйте между играми.

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 -f app
sudo docker compose logs --tail=100 -f proxy
sudo docker compose restart app
```

Ручной откат к сохранённому предыдущему образу (не откатывает конфиг инфраструктуры):

```bash
export BUNKER_IMAGE=$(cat .deploy/previous-image)
sudo --preserve-env=BUNKER_IMAGE docker compose up -d --no-build --wait
```

Не удаляйте образы предыдущих релизов до проверки новой версии. При изменении
самого Compose/Caddyfile нужен отдельно проверенный откат конфигурации.
Не запускайте `docker compose up` без BUNKER_IMAGE: это может выбрать старый
локальный образ. Для обычной выкладки используйте скрипт.

## Домен и HTTPS

Направьте DNS A-запись домена на VPS. В корне рабочей копии создайте `.env`:

```dotenv
SITE_ADDRESS=game.example.com
```

Затем запустите `bash deploy/deploy.sh`. Caddy автоматически получает и обновляет
сертификат. DNS и TCP-порты 80/443 должны быть доступны снаружи. Не добавляйте
AAAA-запись, если IPv6 сервера не настроен. Сертификаты лежат в Docker volume,
поэтому не используйте `docker compose down -v`.

Смена Render-адреса на IP/домен меняет origin: старый localStorage браузера
не переносится, клиент получит новую локальную идентичность. Render можно оставить
как резерв до проверки VPS; сам этот репозиторий старый сервис не выключает.

## Следующий этап: аккаунты и БД

БД не нужна для самой миграции. Следующим этапом можно добавить PostgreSQL
для пользователей, сессий и истории игр, миграции схемы и резервные копии.
Данные БД должны находиться в отдельном постоянном volume, а не внутри образа
приложения; порт БД не нужно публиковать в интернет. Аватары — отдельное хранилище
файлов/объектов, в БД — ссылка. До авторизации обязательно включить HTTPS.
Сохранение истории завершённых партий само по себе не восстанавливает активные
лобби после перезапуска: для этого нужна отдельная логика сохранения состояния.
